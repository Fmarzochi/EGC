# Changelog

All notable changes to EGC are documented here.

## [Unreleased]

### Fixed

- **The full profile delivers the prompt library on every target it names** (#1465): `egc install --target <tool> --profile full` promised 61 agents, 232 skills, 77 commands and 109 rules, but only Gemini, Antigravity, Cursor and CodeBuddy received them. Every skills module depended on `platform-configs`, which names seven targets, and the resolver skipped the whole module wherever that dependency did not apply, so Windsurf, Amp, Copilot and Zed got no skill at all and Claude Code, Codex and OpenCode lost the 38 language and framework skills; the skills modules did not name Kiro, Trae, Junie, Goose, OpenHands, Amazon Q, Qwen, Cline, Aider or Warp; `rules-core`, `agents-core` and `commands-core` did not name Claude Code and most other tools; and the install-state recorded the profile with an empty selection while `egc doctor` called it healthy. Skills modules now stand on their own and name every target; the three library modules name every tool that can hold them (Kiro and Trae kept their own scripts for agents and rules until #1469 replaced them with the Tier 1 adapters; Aider and Warp keep the memory rule only, by design); the `.agents` tree and the root `AGENTS.md` stay with the tools that own them. Claude Code receives the agents in `~/.claude/agents` with the frontmatter Claude Code reads (the tools list as a comma-separated string, a model it cannot run dropped), the commands in `~/.claude/commands`, and the rules flattened in `~/.claude/rules` with their path scopes, without the Chinese mirror of the common rules that would load into every session. `egc doctor` warns when a recorded profile selected no module for its target. A contract test resolves the full profile on all 21 targets and counts what lands.
- **An engine-only install offers nothing it cannot invoke** (#1467): a bare `egc install` writes no install-state, and the routing read that as an unknown installation and kept every catalog entry available, so `orchestrate_task` on an engine-only Claude Code answered `installation: unknown` with agents and skills the install did not have. A tool named by the environment with no install-state is now a known, empty installation: every matching component lands under `not_installed` with the install hint, in the Node routing and in the Guardian's mirror; when the environment carries no harness variable, the Guardian identifies the tool by the client name of the MCP handshake, so one tool is never offered another tool's library. The cognitive protocol's review line sends the agent to the `/review-pr` agents only when the prompt library is installed for the tool (`orchestrate_task` lists what is not installed), and the protocol bumps to v7 so `egc init` and `egc auto-update` rewrite the block on existing installs.
- **The Codex copies in `.agents/skills` are generated from the catalog** (#1471): Codex reads the skills of a checkout from `.agents/skills`, where each real directory carries the `agents/openai.yaml` metadata the catalog does not have and a `SKILL.md` limited to the frontmatter keys Codex accepts. Those `SKILL.md` files were hand copies, and ten of them had not followed the catalog since July (the Exa search skill alone was ninety lines behind). `scripts/ci/codex-mirror.js` now derives them from the catalog (`--write` regenerates, `--check` lists what differs), the ten stale copies are regenerated, `tests/ci/codex-mirror-parity.test.js` fails when a copy drifts again, and the Antigravity guide tells contributors to run the generator instead of copying by hand. The `openai.yaml` files, the `egc` skill that exists only there, and the symlinked entries are untouched.
- **Codex, Goose and OpenHands agree on what lands in `~/.agents`** (#1471): the three tools share that root, and the repository's `.agents` directory, which ships with `agents-core` to the Codex target, carried a stale mirror of the skill catalog under `.agents/skills` (31 skills as real copies without the `origin: EGC` line, the rest as symlinks). Once Goose and OpenHands received the catalog skills flat under `~/.agents/skills` (#1465), those 31 destinations had two sources, the last install overwrote what the others had recorded, and `egc doctor` reported 31 drifted files on `codex-home` right after a clean `egc auto-update`. At a destination both deliver, the catalog copy now wins whatever the manifest order, so the three tools record the same source for the same file; what only the mirror has (the `openai.yaml` metadata Codex reads, the `egc` skill) still ships. A contract test resolves the full profile on the three targets that share `~/.agents` and fails when any destination has two sources, and another asserts no target plans a mirror copy of a file the catalog carries.
- **OpenCode receives the catalog agents in the shape it validates** (#1475): OpenCode parses `~/.config/opencode/agents/*.md` as its own agent definitions and refuses its whole configuration when one is invalid; the catalog agents that #1465 started installing there carried `tools` as a list, a Gemini model id and a named `color`, so OpenCode stopped starting on a machine with the full profile. The agents now land flat through a frontmatter transform: `tools` becomes the object OpenCode reads, with the lowercase tool ids it names (`read`, `grep`, `webfetch`), the model, the stack and the color are dropped, and `mode: subagent` is set, so OpenCode offers them through `@` and the task tool. Doctor and repair compare against the transformed content.
- **Claude Code lists each slash command once** (#1475): Claude Code turns the files of `~/.claude/commands` and the skills into the same slash commands, and three catalog commands (autonomous-lesson-learning, engineering-audit, security-scan) share their name with a skill, so `/` showed them twice. The claude target leaves a command out when a skill of the same plan has its name (a plan without that skill keeps the command); the skill is the richer form and the command only pointed at it. The contract test records the three.
- **`egc install --prompt-library` reaches every detected tool** (#1465): the shell installers only installed the library to Gemini, Codex, OpenCode, Kiro, Trae and CodeBuddy. One Node script now detects every home target by its config directory or its command, applies the full profile to each, reports the ones that failed instead of stopping at the first, and, until #1469 retired them, ran the remaining per-tool scripts when bash was available; both installers call it.
- **The gain test reads a ledger it seeds, not the one the machine happens to have** (#1478 by @kunaaaalcodes, closes #1476): the first case of `tests/crusher-gain-discover.test.js` spawned `scripts/gain.js --history --json` with the real HOME, so it read whatever `~/.egc/metrics/crusher.jsonl` the machine carried. On CI that ledger is empty and the case passed; on a machine that has routed commands through the Token Crusher for weeks the pretty-printed JSON output grows past the 1 MB default `maxBuffer` of `spawnSync`, the child is killed, and the assertion reads `status === null` instead of 0, on `main` as much as on a branch. The case now seeds a one-entry ledger under a temporary HOME, the shape the summary case below it already used, raises `maxBuffer` as a backstop, and asserts the seeded entry comes back verbatim instead of only checking that the result is an array.
- **The health-check test gives a failing stdio server the window its siblings use** (#1481 by @kunaaaalcodes, closes #1460): the case of `tests/hooks/mcp-health-check.test.js` that asserts an unhealthy verdict from a server that writes to stderr and exits ran on the 100 ms budget of the healthy cases. `probeCommandServer` waits that budget and then arms a grace window of the same length before declaring a still-running child healthy, so the stub had 200 ms to spawn Node and exit; on a cold macos-latest runner it took longer, the hook declared it healthy and the assertion saw exit 0 instead of 2 (main at ffc79f1b, one job out of the matrix). The case now runs on the 1000 ms budget of the other unhealthy cases, its wall time unchanged since the server exits at once, and prints the exit code and stderr when it fails. The yarn setup step of the CI workflow also retries `corepack prepare yarn@stable` up to three times, after the tags fetch from repo.yarnpkg.com failed the windows-latest yarn lane on the first push of that PR.
- **The Guardian judges a git force flag by its subcommand and says what it would do** (#1483): `validateGitArgs` refused `--force`, `-f`, `--force-with-lease` and `--force-if-includes` on any git command as "git force-push is forbidden", without reading the subcommand, so `git worktree remove --force` (a disposable working copy) and `git grep -f patterns.txt` (a pattern file) were refused as force pushes, `git commit -F message.txt` too because the scan lower-cased the flag, while `git clean -fdx` passed because no token was exactly `-f` and no rule of its own existed for clean, checkout or rm, and `git push --forc` passed because git accepts any unique prefix of a long option. The flag is now judged per subcommand through a table that fails closed: push, checkout, switch, rm, mv and submodule are refused with a reason that says what the command would destroy and what to do instead; clean is refused unless it is a dry run, with the value of `-e` never read as `-n`; worktree is allowed with its path checked against protected paths; grep, config, log, diff, show, blame, status and the other read-only subcommands are exempt because a short `f` there names a file or a format; every other subcommand carrying a force flag is refused as not on the safe list. A long option is read as the option it abbreviates, short flags keep their case, an alias (inline or persisted) is validated as the command it expands to, the file operand of `git config -f` on a protected path is refused, and the subcommand name in the reason is reduced to the characters a subcommand can have so an advisory marker in the input cannot downgrade the block at the hook layer. The bot review and an external audit of the branch added the spellings git also accepts (the file operand attached to `-f` or under an abbreviated `--file`, `--no-dry-run` after `-n`, `-n` as a pathspec after `--`, an abbreviated `--exclude`, the pattern file of `git grep -f` on a protected path, a worktree path after `--`, the command's cwd carried into the alias check) and closed the older weakness behind the marker check: every verdict of `validateCommand` now carries an `advisory` field, true only for the allowlist miss and the shell metacharacter verdicts, and the enforcement hook reads that field when present, so no alias key, path or config key can soften a hard block by carrying an advisory phrase. The validator itself stopped reading that phrase too: the step that lets the allowlist miss fall through to the metacharacter check now asks the verdict, so a protected path named after the phrase no longer walks out of the denial it had just earned. One hundred and three new cases pin the policy, and each of sixteen mutations on the compiled build fails only the cases that cover it.
- **The Crowdin sync translates what it uploads** (#1505): the machine-translation step added in #260 asked Crowdin to pre-translate without the `fileIds` the API requires and listed every language the engine covers instead of the languages the project targets, so the request was refused on every run since at least 2026-07-18, the refusal became a warning, the download found nothing and the run stayed green; the translations stopped at 2026-08-03 while the README changed four times. The step now reads the target languages and the file ids from the project, keeps only the languages this repository ships (`translations/<dir>`, with pt-PT and pt-BR mapped to pt and es-ES to es), sends both, and fails the run with the API's status and answer when any of those lookups is refused, when the request is refused, or when the pre-translation ends failed, canceled or unfinished; a language directory the repository does not track is dropped after the download, since adding a language is a decision, not a sync. The first live run translated the seven shipped languages the engine covers (Arabic, German, Spanish, French, Italian, Portuguese, Chinese); Hindi, Korean and Turkish are outside the engine's pairs and Japanese and Russian were requested but did not export as complete, so those five stay as they were until the panel says why.
- **A script handed to `egc run --shell` is validated segment by segment** (#1503): #1487 unwrapped `egc run` so the wrapped command is the one judged, and for `--shell` it re-read the quoted script as a command line. A compound script (`egc run --shell "ls && rm -rf x"`) still came back as the advisory metacharacter verdict, which the enforcement hook lets through, so a refused command could ride inside a script a shell would run. The hook now reads the script of `egc run --shell` the way it reads a heredoc a shell consumes: the words after the one option `egc run` reads (`--shell` as its first argument, the way `scripts/crush-run.js` parses it) are joined, split into segments, and each segment is validated on its own, behind wrappers too and even when the script starts with a dash. Six cases pin it, including the segment list itself.
- **The contributing guide lists the twelve translations the repository carries** (#1506): its "Current translations" table named Spanish and Portuguese with hand-kept percentages while `translations/` holds twelve languages, all complete by construction of the sync; the table now lists the twelve files and says that progress per language lives in Crowdin.
- **The context files receive project memory only after the commit-privacy filter is in place** (#1510): the memory block is mirrored into a repository's `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` and editor rules on every session start and every `update_state`, and the git clean filter that keeps it out of commits is armed right before each write. The mirror now waits for the filter's verdict: in a checkout where it cannot be set up (git cannot open it, the filter script is not on disk, the local configuration cannot be written), the files are left as they are, the result reports nothing written, and one line on stderr says why and points at `egc doctor`; the memory itself stays in `~/.egc/state`, and outside a repository nothing changes. The filter planner tells a checkout git cannot open apart from a directory that is no repository, so `egc init` and the installers print the real reason. Three suites pin it, red before the change and green after.
- **A Bash command runs only after the installed validator returns a verdict** (#1511): the Guardian hook asks the validator for a verdict per segment before every command; a validator that stalls past its budget, stops, or answers something the hook cannot read (an empty or partial list, or an entry without a verdict, included) now blocks the command with one line that names the reason, says nothing was executed, and points at `egc doctor`, at `EGC_GUARDIAN_TIMEOUT_MS` to raise the budget on a slow machine (four seconds by default), and at `EGC_DISABLED_HOOKS=pre:bash:guardian-validate` to lift the gate during a repair. A machine without the validator build keeps its behavior and is never locked out. The bridge in `scripts/lib/guardian-bin.js` says which of the four things happened; the hooks that only lose a hint when an answer is missing keep failing open. Five cases pin it.
- **The target of a redirection meets the same protected paths as any other operand** (#1512): the shell opens the target of `>`, `>>`, `>|`, `>&`, `&>`, `<` or `<>` on the command's behalf, with the operator glued to the target as much as spaced from it, before the command or behind a wrapper, whatever command stands in front. The validator now reads every redirection of the command line before the per-command checks and refuses one that writes onto a protected file or reads a credential, with a reason that names the file and says what to do; descriptor duplications (`2>&1`, `>&-`), heredocs (their bodies too, up to the terminator line), here-strings and a quoted or escaped operator name no file and are left alone. The command line is read the way the shell reads it (a backslash before a newline joins the lines, single quotes literal, inside double quotes only the escapes the shell allows, a backslash outside quotes escaping the next character, a parameter expansion in braces as text, a command substitution or backquotes as a command of their own whose redirections are read in turn), and on Windows, where a backslash separates path components, the target is also checked as typed. A path that starts with `$HOME` or `${HOME}` names the home directory in every path check, as `~` already did. Fifty-one cases pin it.
- **The shim tests start their children from an environment without the raw flag** (#1514): the cases of `tests/lib/crusher-shim-dispatch.test.js` spawned the shim with the environment of the suite, so a suite started from a shell that had exported `EGC_CRUSHER_RAW` (the flag `egc run --raw` sets for its children) saw a passthrough where a case expects compression and failed on a working machine while CI, whose shell has no such flag, stayed green. The children now start from a copy of the environment without that flag; the case that exercises the flag sets it on its own.
- **The memory block survives a checkout, a pull and a stash** (#1513): the commit-privacy filter keeps populated memory out of every commit through its clean side, and until now its smudge side was an identity, so whenever git wrote one of the context files anew (a pull that touched it, a branch switch, a stash pop) the working tree came back with the zeroed blob and the block only returned at the next propagation, which Cursor, Copilot or Windsurf, reading those files directly, never trigger. The smudge now puts the memory back: git hands it the zeroed blob and gets the block of the local state in return, the way propagation writes it, with the llms.txt shape for llms.txt, and the file reads as unmodified to git afterwards. It never fails a checkout: a layout without the state readers next to the script, a project without state, a state that cannot be read or a file without the markers all get the content back as it came. Both configuration paths write the smudge command with a fallback that hands the blob through as committed when node or the script is not there, decided before anything reads the blob, so a checkout never waits on it, while a failure to write is loud so git holds the checkout instead of keeping a truncated file; a driver hardened without the script on disk keeps the identity. The block goes out without its update stamp, since git runs the filter before the branch pointer moves on a switch, so the next propagation makes it the branch's own; bytes that are not UTF-8 and a state that is a link go out as they came; the text of a marker never travels inside the block, for the smudge and for the mirrors alike; a file git checked out with CRLF keeps CRLF on every line of the block. The clean side now zeroes the llms.txt shape of the block too (its context paragraph and next-session list kept their text before), reads a file with CRLF line breaks, and the leak check reads the llms.txt heading. Nineteen cases pin it, a repository path with spaces, a linked worktree and a branch switch among them.
- **A context file rewritten by propagation reads as unmodified to git** (#1516): git trusts the size it recorded for a file and does not run the clean side of the filter until the entry is looked at again, so a branch switch after a session start was refused for a mirror that carried nothing new; both propagators now clear the recorded stat of the files they wrote and refresh those files alone, so a mirror that still cleans to the committed blob reads as unmodified, a change of the user's own stays an unstaged change, an entry that carries a mark (skip-worktree, assume-unchanged, intent-to-add) is left as it is, and nothing is ever staged. Thirteen cases pin it, and the branch-switch case of the filter suite proves the round trip without help.
- **The pre-commit hook and the commit-privacy filter keep one and the same skeleton** (#1517): the hook of this repository passes a staged context file through the clean side of the filter instead of cutting the block out on its own, re-stages it only when the hash changes, and stops the commit with a line that says what is missing when node or the script is not at hand; the six context files are committed through the filter, so a clone with the filter armed reads them as unmodified after the propagation. Seven cases pin the hook, and two more pin the clean side: the skeleton a smudged file cleans back to (the triggers the propagation writes after the memory go with it), and bytes outside the block that are not UTF-8.
- **A protected path meets the same denial in every spelling** (#1515): the shell removes the quotes and resolves the escapes of an argument before the command sees it, and the Guardian's per-command path checks (git worktree and config, grep, cat, find, head, ls, stat, node and the other dev tools) judged the argument as typed, so a credential or a credential store named between quotes, with an escaped character or with a space in its name was another spelling than the file the command would open. Every check now reads each argument as the word the shell hands over (quotes removed, escapes resolved, ANSI-C quoting decoded, a continued line joined), so a flag between quotes is the flag it is (a find action, a grep pattern file) and a protected path meets its denial in every spelling; a brace expansion runs where the shell runs it, on every word of the line (the command word and the wrappers included, since `r{m,}` names `rm`), before quote removal and into the arguments it names, only where the braces stand outside quotes and unescaped, and a word with more expansions than the check reads refuses the whole command; on Windows, where a backslash separates path components, the argument with only its quotes removed is judged as well; and the scan for the commands outside the catalog derives its candidates from the same spellings, so a value glued to a quoted short flag is judged too. The find checks read the starting points only (the words before the expression, after the `--` that ends the options), so a name pattern such as `-name "*.env"` is a search and not a path, and `-fprint` and `-fprint0`, which write a file, join the actions find is refused with. Forty-three cases pin it.
- **Every session bus call acts as its own session, inside the project it joined** (#1525): the bus identity is the server process that runs it, and the project is the one the session joined with its first memory call or project-scoped bus call (the working directory when no `project_path` is given; `claim_path` and `release_path` carry no project). `session_announce`, `session_send`, `session_events`, `session_wait`, `session_peers`, `claim_path` and `release_path` refuse another session's id or another project with a reason that says to leave it out, and an omitted project means the session's own; a direct event reaches only a live session of the same project; `session_peers` lists the sessions of that project while the lock list stays global; and a memory call on another project refreshes the heartbeat where the session joined without moving it.
- **The memory server waits for a store lock held at startup instead of exiting** (#1526): the server opens its store before it accepts MCP requests and now sets the busy timeout before switching the store to WAL, so a lock held at that moment by another process (a second tool starting at the same time on a fresh machine, a migration in flight) is waited for like every later query instead of ending the process with `SQLITE_BUSY`.
- **Project memory is written only into regular files inside the project** (#1528): the memory server and the session hooks mirror the memory block into a context file only when the file is a regular file and no folder between the project and the file is a link, so a context file or a tool folder that is a link, a Windows junction included, is left as it is together with whatever it points at, and the context files beside it are written as before.
- **A decision the user asks to remember reaches the next session** (#1531 by @Akisolu, closes #1524): the protocol sent "remember this decision" to `store_decision`, whose description promised that `get_state` would surface it, while its rows only feed `query_history` and `search_history`. A decision now goes to `update_state` (its `decisions` field), `store_decision` stays the searchable decision history with a description that says so, and "what did we decide" checks `get_state` before the history tools, in every copy of the protocol and in the `egc-context` mirrors the state propagator writes. The protocol moves to v8 so installs already in place receive the new route, and a mirror at the same state stamp is rewritten when its generated block changed, so the route reaches mirrors already in place too.
- **A lesson is stored and handed back as data** (#1533): `lesson_save` checks `content`, `context`, `tags` and `author` the way `store_decision` and `update_state` check their fields and refuses text that reads as an instruction to the model, in one field or split across them, so the agent can rephrase and save again. `lesson_recall` and `lesson_reinforce` hand back a stored field that reads as one as the blocked marker, never as its text, so every lesson in the store, whatever wrote it, stays visible and comes back as data. The full-text recall path carries the author like the substring path does.
- **A new OpenCode session opens with the project memory again** (#1530 by @Akisolu, closes #1529): OpenCode runs its plugins inside its own runtime, so `process.execPath` there is the OpenCode binary and the session restore never started. The restore child now starts from `process.execPath` only when that is Node, and otherwise from a Node found on an absolute `PATH` entry, instead of looking `node` up in the project folder it runs in; when none is found, the session opens without memory instead of failing.
- **An inline `mcp_servers` array no longer breaks a TOML config on install** (#1521 by @Rishindra1430, part of #1497): TOML forbids an inline `mcp_servers = [...]` next to the `[[mcp_servers]]` tables the registrar appends, and `vibe mcp remove` leaves an empty one behind, so Codex or Mistral Vibe refused to start after an install. The registrar now reads the root table the way TOML does (it stops at the first table header, skips comments and multi-line strings, accepts the quoted spellings of the key), removes an empty inline array before appending, leaves a non-empty one untouched with a clear message, and, where the TOML parser is installed, checks before writing that the result still parses and keeps everything else in the file unchanged.
- **A tool config reached through a link is written only where the link stays under its folder** (#1538): `egc init` and the shell installers merge egc-guardian and egc-memory into the config of every detected tool, and a config kept in a dotfiles folder and linked into place is still written through the link. The destination of that write is now resolved the way the filesystem resolves it (the file, every folder above it, and a link to a file that is not there yet), and the config is written only when it lands under the home folder or under `$XDG_CONFIG_HOME`; anywhere else the tool is skipped with a note that names the file and where it leads, and nothing behind the link is read. The project `.mcp.json` the shell installers merge into follows the same rule with the project folder as the boundary, and when the servers go into OpenCode's `opencode.json`, a legacy `config.json` beside it that is a link is left as it is.
- **The install lifecycle follows a link to a file that is not there yet** (#1539): repair and uninstall replay only the destinations that stay inside the roots an adapter owns, judged by where the write lands with every link on the way followed. That now includes a link to a file that is not there yet, followed from the folder the link really sits in, so such a destination that leads outside the roots is refused like any other. The MCP registrar of #1538 uses the same walk instead of its own copy.
- **A tool config is replaced in one step** (#1540): `egc init` and the shell installers write each tool config the way the installer writes its own files: the text goes to a temporary file beside the config, created exclusively with the config's mode, reaches the disk, and is renamed over the previous file, so a write cut short leaves the previous config whole. The write lands where the path really leads, so a dotfiles link keeps pointing at the updated file. An existing config keeps its mode, and its owner when the install runs as root; a config its owner made read-only is left as it is when the install runs as a regular user (root writes it, as the write in place did); a config created here is readable by its owner only. Where the folder or a mount does not allow the replacement (a read-only folder holding a writable config, a config mounted on its own, a file another program holds on Windows), the config is written in place as before.
- **A TOML config keeps any install path as one string** (#1541): the registrar writes the egc-guardian and egc-memory paths into the TOML configs of Codex and Mistral Vibe as TOML basic strings, and now escapes every control character in them along with the backslash and the double quote: a line break, a carriage return, a tab, a backspace and a form feed take their short TOML form and any other one takes `\uXXXX`, so the config parses whatever the install folder is called. The reader that finds egc-guardian through the Codex config reads every one of those escapes back, and `\UXXXXXXXX` too.
- **A wrapper's options are read the way the wrapper reads them** (#1542): the Guardian looks through sudo, doas, env, exec, timeout, nice, ionice, stdbuf, xargs, flock, watch, strace, time, systemd-run and parallel to judge the command they run, and now reads their options the way getopt does. Short flags grouped in one word (`-Hu root`) are read letter by letter up to the first letter that takes a value, and that value is the rest of the word or, when nothing is left, the next word; an optional value (`xargs -i`, `watch -d`) is only ever attached; a long flag written with `=value` keeps its value to itself. The tables list every option that takes a value, checked against each tool's own parser: sudo `-a`, `-c` and `-T`, doas `-a`, env `-a` and `-f`, exec `-a`, ionice `-u`, watch `-q`, the strace value options and the systemd-run timer and property options joined the ones already there. `env -S` is recognized inside a group of flags and with its value attached, and `flock FILE -c` joins it: both hand a string over to be run as a command and are refused the same way.
- **validate_write judges a relative path where the agent works** (#1544): the tool takes an optional `cwd`, the directory the agent works in, and resolves a relative `filepath` against it (a leading `~` expanded, a trailing line break dropped) before checking the protected paths; a `cwd` that is still relative once `~` is expanded is refused instead of guessed, and without `cwd` the server's own directory is the base, as before. The audit trail records the path that was judged. The write hook already resolved a relative target against the directory the harness reports.
- **The dashboard answers only to its loopback names** (#1545): every request is checked before any route, `/ops` and the page that carries the dashboard token included, and one whose `Host` is not `localhost`, `127.0.0.1` or `[::1]` (any valid port, any letter case) is refused with 403, as is an HTTP/1.0 request that sends no `Host`; the WebSocket upgrade needs a loopback `Host` as well as the panel's origin. A forwarded or mapped port keeps working under a loopback name.
- **The Economy tab shows a provider name as text** (#1546): a provider the panel does not know is labeled with the raw id the telemetry carries, and that label now goes through the same escaping as every other value the panel renders.
- **A wrapper's long options are read in any abbreviation the wrapper accepts** (#1548): getopt_long takes a unique prefix of a long option as that option, so the Guardian now does the same when it looks through a wrapper (`sudo --us root`, `timeout --kill 5`, `env --split`), while an exact name keeps its own meaning (`sudo --login` next to `--login-class`, `strace --stack-trace` next to `--stack-trace-frame-limit`) and an ambiguous prefix, which the wrapper refuses, is left as written. `systemd-run --json` and `strace --stack-trace-frame-limit` join the value options.

- **`egc export` prints the memory document for a project or the global scope, decrypted, as text or JSON**: the reference implementation of section 8.1 of the Agent Memory Interchange spec. `egc export` resolves the current directory to its branch state like `get_state` does (`--project <path>` picks another project, `--scope global` the user-wide memory) and prints the stored document byte for byte without the encryption header or the integrity sidecar; `--json` parses the header fields and the five sections, keeping unknown sections aside. The command is read-only by contract: the state file is read through a checked descriptor (never through a link, a regular file inside the state directory, the way the doctor reads it), the key is loaded without changing its mode (a key readable by others is refused, not tightened), and nothing is written, not the state files, not the key, not the sidecars. ## [1.1.9] - 2026-07-11

### Security

- **`egc-memory`: TOCTOU race in encryption key generation eliminated**: `loadOrCreateEncKey` used to leave a window where a concurrent process (e.g. a background agent's own `egc-memory` server starting before `~/.egc/encryption.key` existed) could read a key file that was created but not yet fully written. In the original exclusive-write approach, it could also silently generate and cache its own discarded key for the rest of the process lifetime. Key publication is now atomic (write-to-temp plus `fs.linkSync`), so a racing reader either sees no file or a fully-written one, never a partial write. (#696)
- **`resolveProjectPath`: cwd/PWD fallback fixed**: `process.cwd() || process.env.PWD` never reached the `PWD` fallback, because `process.cwd()` throws rather than returning a falsy value when the working directory is unavailable. Now wrapped in try/catch so the documented fallback actually triggers. (#696)

### New Features

- **`update_state`: recovery path for undecryptable state files**: a state file that fails to decrypt (corrupted, or encrypted under an orphaned key from a race) used to permanently block every future `get_state`/`update_state` call for that project, with no sanctioned way to recover: not through the tool itself, and not through the EGC Guardian, which blocks raw shell access to `~/.egc/state/**` by design. `update_state` now accepts an optional `force: true`: when the existing file cannot be decrypted, it is quarantined (renamed to a `.corrupted-backup-<timestamp>` sibling, never deleted) and the call proceeds as a fresh write instead of aborting forever. (#697)

### Contributing

- **Concurrent-access regression tests required**: `CONTRIBUTING.md` and the PR template now require a concurrent-access regression test for any change touching a file shared across concurrent EGC processes (encryption key, state files, install-state, lockfiles under `~/.egc/`), citing the TOCTOU bug above as the motivating example. This bug class is invisible to CodeQL, SonarCloud, and the full test matrix, since none of them reason about interleaving between separate process executions. (#697)
